Capstone · Structure from Motion

System architecture

A classical Structure-from-Motion pipeline written from scratch in Python. The geometry — epipolar estimation, pose recovery, triangulation, resectioning and bundle adjustment — is implemented, not called. Libraries are used only for feature detection, dense block matching and surface meshing. This page is the structural view: the layers, what each package owns, the rules the dependency graph obeys, and the two contracts everything passes through.

Layer view

Four layers, one direction

Every arrow in this system points downward. Scripts call the library; the library reads and writes shared state; only two packages touch anything outside the project. Nothing in the core library imports a script, and nothing in a lower layer imports a higher one.

Dependency graph

Three tiers, no cycles

Every module sits in one of three tiers by how deep its import chain goes. Tier 0 imports nothing from the project at all. Tier 1 imports only tier 0. Tier 2 is as deep as the graph gets. A module can only import from a strictly lower tier, which is what keeps the graph acyclic and keeps any single stage testable in isolation.

Invariants

Five rules the structure holds to

These are properties of the import graph as it stands, not aspirations. Each one buys something concrete.

01

map.py imports nothing and is imported by seven modules

It holds Camera, Point3D, Observation and Map — the shared scene graph. Because it depends on no other part of the project, it can sit at the centre of the system without creating a cycle, and every stage that mutates the scene speaks the same vocabulary.

02

geometry/ imports nothing but itself

Three of its four modules import no project code at all; the fourth, essential.py, imports only triangulation.py for the cheirality test. The epipolar mathematics has no knowledge of file formats, of the scene graph or of the incremental loop, so each estimator can be tested against synthetic data with nothing else loaded.

03

mvs/ and eval/ import nothing from the rest of sfm/

Both take plain NumPy arrays. That is the reason scene_cache.npz works as a hand-off: dense reconstruction and evaluation can run against a finished solve without the pipeline, the scene graph, or even the original photographs being loaded.

04

The bundle adjuster is injected, not imported

recon/incremental.py imports ba/scipy_ba.py as a default and never imports ba/lm.py. The hand-written Levenberg–Marquardt solver is passed in as bundle_adjust_fn by the calling script. The two solvers share an interface, so the same loop runs on either — which is what made measuring one against the other possible at all.

05

Scripts are the only layer that knows about datasets

No module in sfm/ contains a dataset path, with the single deliberate exception of io/fountain.py, which exists to encapsulate one benchmark's fixed layout. Everything else takes a folder and a camera matrix.

Data contracts

Two hand-offs, and nothing else

All state in the system passes through one of these. The first lives in memory for the length of a run; the second survives it.

In processsfm/map.py

The scene graph that every core stage reads and mutates. Observations live in one flat list with two index dictionaries pointing into it, so bundle adjustment can walk one point's views or one camera's views without scanning the whole set.

# the four types
Camera      id, K, R, t, width, height
Point3D     id, xyz, color
Observation camera_id, point_id, uv
Map         cameras, points, observations
            + index by camera, index by point

Written by recon/, refined by ba/, coloured by io/colorize.py, serialised by io/ply.py.

On diskscene_cache.npz

The boundary between reconstruction and everything downstream. Deliberately plain: eight NumPy arrays and no project types, so evaluation, dense stereo, figures and the web viewers all read a finished solve without importing the pipeline or re-running it.

# outputs/<dataset>/scene_cache.npz
cam_ids   (N,)      Ks       (N,3,3)
Rs        (N,3,3)   ts       (N,3)
widths    (N,)      heights  (N,)
xyz       (M,3)     colors   (M,3)

Written by reconstruct.py; read by twelve scripts, including every evaluation and figure path.
