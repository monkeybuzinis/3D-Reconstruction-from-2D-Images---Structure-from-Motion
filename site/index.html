3D reconstruction from photographs

A classical Structure-from-Motion pipeline built from scratch. Camera positions and 3D geometry are recovered from overlapping photographs by multi-view geometry — no deep learning, no Gaussian splatting, no generative models. Every point below was measured, and every reconstruction is interactive.

Where the line is drawn

The project's rule was to build a working pipeline with trusted libraries first, then replace each piece of the geometry with hand-derived code. Feature detection and the dense-stereo back end stay library-backed on purpose; they are solved problems that aren't what this project is about.

derived and implemented hereThe geometry

  • Hartley normalization + normalized 8-point algorithm + RANSAC for the fundamental matrix
  • E = KTFK, four-way decomposition, cheirality check to resolve the ambiguity
  • DLT triangulation
  • Calibrated DLT resectioning (PnP) + RANSAC
  • Levenberg–Marquardt bundle adjustment: analytic Jacobian, so(3) rotations, Schur-complement solve
  • Umeyama similarity alignment; accuracy / completeness / F-score

deliberately library-backedThe scaffolding

  • SIFT + FLANN feature matching (OpenCV)
  • scipy.optimize.least_squares — the first working bundle adjuster, kept as a baseline the hand-written solver is measured against
  • cv2.StereoSGBM + WLS filtering for per-pixel dense stereo
  • Open3D Poisson surface reconstruction

What measurement found

Four defects that passing tests and plausible-looking output did not reveal. Each was caught by checking a number against something independent, and each is recorded with what it cost.

01

Linear PnP is degenerate on flat scenes

RANSAC found a good pose, then the code refit using every inlier and returned that — but DLT resectioning gets worse on near-coplanar points, and a church facade is exactly that. Cameras were "succeeding" with 0–4 real inliers.

→ Registered cameras 11/23 → 21/23; outlier keep-rate 14% → 88%
02

Cheirality tested in the wrong coordinate frame

Depth was read as world Z, which is only camera depth for the one camera that defines the world origin. Found by code review rather than a crash, and it affected 97.6% of triangulations.

→ Recovered 1,148 valid points — which turned out to be a second building in the scene the old test had discarded wholesale
03

Dense parameters derived from world coordinates

The depth window and voxel size were read off the sparse cloud's world-Z percentiles. Once the cheirality fix admitted points behind the origin camera, that window went negative, then — on another dataset — to 5,029,180 against a median depth of 4.

→ Now from per-camera depths and the sensor's resolution limit; Fountain's mesh went 85,981 → 202,118 triangles
04

"Keep the largest cluster" discarded real structure

Keeping only the biggest connected component assumes the surface is one blob, but windows and occlusion gaps split a facade into several.

→ Rathaus was keeping 34% of its building; an entire 4,466-point wing was being thrown away as noise

Where it stops working

Incremental SfM needs consecutive views close enough to share features. Sorting every dataset by how far the camera moves between shots, relative to how far away the subject is, shows the boundary precisely — and the one capture that crosses it.

The Buddha capture orbits a convex object on a sphere at 15.8° steps, so each surface patch appears in only a few views and the registration loop runs out of correspondences. Its two-view geometry is still accurate to 0.137°; what fails is chaining those pairs into one global solution.

Reproduce it

# any folder of photos → sparse cloud, cached scene, dense mesh
.venv/bin/python3 scripts/reconstruct.py path/to/photos --dense

# build the interactive viewer for a finished reconstruction
.venv/bin/python3 scripts/export_viewer.py outputs/<dataset>

# per-stage checks on the Fountain-P11 benchmark
.venv/bin/python3 scripts/verify_two_view.py      # F, E, pose, triangulation
.venv/bin/python3 scripts/verify_ba_jacobian.py   # analytic Jacobian vs. finite differences
.venv/bin/python3 scripts/verify_hand_ba.py       # hand-written Levenberg–Marquardt
.venv/bin/python3 scripts/verify_evaluation.py    # Umeyama alignment + F-score
.venv/bin/python3 scripts/verify_cheirality.py    # cheirality regression test
Camera intrinsics come from a dataset's own calibration where one exists, otherwise from EXIF, and only as a last resort from an assumed field of view — which is the single largest factor in whether a self-captured set reconstructs at all.
